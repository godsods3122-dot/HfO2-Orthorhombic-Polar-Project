# parent_pristine — Weyl phonon 있음 (Simphony 확정)

Simphony(패치본, 이 세션 gfortran 빌드)로만 조사. phonopy 는 노드 탐색과 교차검증에만 사용.
외부 문헌 참조 없음. `source/parent_pristine/`.

## 0. 결론

**band 17-18 에 진짜 Weyl phonon 이 있다.**

`(k1, k2) ≈ (0.1464, 0.0709)` 에 **k3 방향으로 3개가 일렬로** 늘어서 있다.
모드 주파수는 셋 다 **10.087 THz = 41.72 meV = 336.5 cm⁻¹**.

| k (환산) | gap (THz) | χ (Simphony) | χ (Berry flux) |
|---|---|---|---|
| (0.1464400, 0.0710381, **+0.0049255**) | 0 | **−1** | +1 |
| (0.1464927, 0.0708493, **0**) | 0 | (0, 아래 3절) | −1 |
| (0.1464400, 0.0710381, **−0.0049255**) | 0 | **−1** | +1 |
| **세 개를 감싸는 구 (R=0.010)** | — | **−1** | **+1** |

두 방법의 전체 부호 규약이 반대다(크기·상대부호는 일치). **합 규칙이 양쪽에서 맞는다**:
−1 + (+1) + (−1) = −1 (Simphony), +1 + (−1) + (+1) = +1 (Berry flux).

거울지표가 k1, k2 이므로 각 노드는 **4점 궤도**를 이루고 χ 가 교대한다.
Simphony 직접 확인 (Nk=100, R=0.002):

```
( 0.14644,  0.07104, 0.00493) -> -1
( 0.14644, -0.07104, 0.00493) -> +1
(-0.14644,  0.07104, 0.00493) -> +1
(-0.14644, -0.07104, 0.00493) -> -1
( 0.14644,  0.07104,-0.00493) -> -1
```

즉 이 계열은 BZ 전체에 **12개**(3 × 4점 궤도)다.

## 1. 해밀토니안 검증 — Simphony = phonopy

세 노드를 관통하는 선(k3 = −0.01 → +0.01, 81점)에서 `BulkBand_calc` 대 phonopy:

```
전 36밴드 최대 |simphony − phonopy| = 2.294e-07 THz
band17-18 국소최소  simphony: k3=±0.005 에서 6.83e-06
                   phonopy : k3=±0.005 에서 6.83e-06   (동일)
```

레포 허용오차 3.4e-7 THz 안에 든다. **비전치 LOTO_BC + `Package = 'Phonopy'`** 조합이며,
`scripts/input.py` 가 이제 이 둘을 기본으로 낸다.

## 2. 전역 탐색 (기약 쐐기 41³)

```
쐐기 최소 gap = 2.01e-10
gap<0.02 국소최소 36개 → 거울면 위/수렴 33개, 일반위치 3개
   (0.1464400, 0.0710381, 0.0049255)  gap=8.9e-15   <- 위 Weyl 계열
   (0.2499400, 0.1370633, 0.5000000)  gap=8.8e-09   <- k3=0.5 nodal plane
   (0.4683408, 0.4643373, 0.5000000)  gap=1.8e-08   <- k3=0.5 nodal plane
```

k3 = 0.5 는 편극축 2₁ screw + 시간역전이 축퇴를 평면 전체에 강제하는 자리다.
Simphony 도 그 둘에 대해 **χ = 0** 을 준다 (강제된 값과 일치).

**따라서 band 17-18 의 Weyl 은 위 한 계열뿐이다.**

## 3. ⚠️ 중요한 함정 — `Nk1`, `Nk2` 를 100 이상으로 둘 것

이 노드들은 매우 **무르다**. 반지름 0.0015 인 구 위에서 gap 이 겨우 ~1e-4 THz 다.
Simphony 의 구면 Wilson loop 은 `Nk1 × Nk2` 로 이산화되는데, 격자가 성기면
감김을 놓치고 **조용히 0 을 돌려준다**:

| Nk1 = Nk2 | 결과 |
|---|---|
| 15 | 전부 0 ← **거짓 음성** |
| 50 | 전부 0 ← **거짓 음성** |
| **100** | **−1, +1, +1, −1, −1** (정상) |

`input.py` 기본값이 50 이므로 **그대로 쓰면 Weyl 을 놓친다.**

바깥 두 노드는 Nk=100 에서 풀리지만, **가운데(k3=0) 노드는 Nk=200, R=0.001 에서도
Simphony 가 0 을 준다.** 그런데 세 개를 감싸는 구(R=0.010, Nk=200)에서는 −1 이 나온다.
가운데가 0 이라면 합이 −2 여야 하므로, **Simphony 자신의 합 규칙이 가운데 노드가
0 이 아님을 말해 준다.** 독립 Berry flux 도 반지름 0.0005~0.002, 격자 32×64 / 48×96
전부에서 −1 로 흔들림 없다. 가운데 노드의 개별 값 0 은 Simphony 쪽 수렴 실패다.

## 4. 이전 세션 결과가 왜 틀렸었나

`results/weyl_trend/SUMMARY.md` 는 parent_pristine 에 대해 "후보 3개, chirality 전부 0"
이라고 적었다. 그 계산은 **전치 LOTO_BC** 였고 `Package` 줄도 없었다. 이번에 측정으로
확인된 바:

- 전치 LOTO_BC 는 전 36밴드에서 phonopy 와 1.8e-1 THz 어긋나고 Weyl 자리에서 gap 이
  닫히지도 않는다 (비전치는 2.3e-7 일치).
- `Package` 줄이 없으면 기본값 `'QE'` 라 `readHmnR` 이 스피너용 `reorder_wannierbasis`
  를 태운다. 고윳값은 permutation 이라 안 변해 **밴드는 멀쩡해 보이지만** Wilson loop
  이 망가진다.
- 거기에 `Nk1=Nk2=50` 의 거짓 음성까지 겹쳤다.

세 가지가 전부 **"조용히 0"** 으로 수렴하는 실패 양상이라 알아채기 어려웠다.

# 추가 조사 — BulkGap 을 고쳐서 Simphony 자체로 재확인

"노드끼리 너무 가까운 게 문제 아니냐", "BulkGap 으로 하라"는 지적에 따라 다시 봤다.
지적이 둘 다 맞았고, 앞 절의 결론은 유지된다.

## 6. `BulkGap_cube_calc` 가 LO-TO 를 건너뛰고 있었다 (패치함)

앞 절에서 "BulkGap 은 이 빌드에서 쓸 수 없다"고 쓴 것은 **원인 진단이 틀렸다.**
진짜 원인은 `fermisurface.f90` 의 `gapshape3D` 가

```fortran
call ham_bulk_latticegauge(k, Hamk_bulk)     ! ← 무조건
```

를 부른다는 것이다. `ek_bulk.f90`, `wanniercenter.f90` 은 모두

```fortran
if (index(Particle,'phonon')/=0.and.LOTO_correction) then
   call ham_bulk_LOTO(k, Hamk_bulk)
else
   call ham_bulk_latticegauge(k, Hamk_bulk)
endif
```

로 분기하는데 `gapshape3D` 만 빠져 있다. hr.dat 에는 dipole-dipole 성분이 빠져
있으므로(`phonopy2TBDAT --born` 이 빼서 쓴다) 이 경로는 **단거리 힘상수만의
스펙트럼**을 준다. 그래서 Ev/Ec 가 3.5–4.6 THz 로 나왔던 것이다.

→ **`patch/apply_gapcube_loto_fix.py` 로 고쳤다.** 원 패치의 후속편이며 단독 실행
가능하고 멱등이다. 적용 후 41³ 스캔이 17초 → 49초로 늘어나고(LO-TO 비용), 결과가
phonopy band 17-18 과 일치한다.

**단위 주의**: `gapshape3D` 의 Ev/Ec 는 THz 주파수가 아니라 **동역학 행렬 고윳값**,
곧 `ω²(THz²) × 0.036749` (eV→Hartree) 다. 검증:

```
Ev = 3.69304   <->  phonopy band17 = 10.02461 THz
10.02461² × 0.036749 = 3.69304        (일치)
```

따라서 파일의 `gap` 은 Δω 가 아니라 Δ(ω²) 이고, 노드 근방에서

```
gap_file ≈ 0.073498 × ω̄(THz) × Δω(THz)      (여기서는 ω̄≈10.1 → 나눗수 0.742)
```

검증: 파일 9.6341e-3 vs 0.073498 × 10.59 × 1.2367e-2 = 9.63e-3 (일치).
**0 은 어느 쪽이든 0 이라 노드 탐색에는 그대로 써도 된다.**

## 7. 고친 BulkGap 으로 본 클러스터

전 BZ 41³ 스캔은 이 노드들을 **못 잡는다** — 너무 날카로워서 격자 간격 0.0125 로는
문턱 아래로 안 내려온다. (그 스캔에서 나오는 낮은 gap 점들은 전부 거울면·k3=0.5
nodal plane 에 인접한 격자점의 꼬리다.) 클러스터 주변만 고해상도로 훑어야 한다:

```
KCUBE_BULK  원점 (0.1380, 0.0630, -0.0100), 변 (0.0170, 0.0160, 0.0200), 51³
→ 최소 gap_file 7.119e-05 (Δω≈9.6e-05 THz)
→ 국소최소 4개: k3 = ±0.0044 와 ±0.0080  (k1,k2 ≈ 0.1465, 0.0710)
```

## 8. 노드는 정말 3개다 (독립 확인)

BulkGap 격자는 (k1,k2) 를 고정한 열에서만 보므로 k3=0 노드를 놓친다 — 최소점의
**면내 위치가 k3 에 따라 이동**하기 때문이다. k3 를 고정하고 (k1,k2) 로 최소화하면:

| k3 | k1 | k2 | min gap (THz) |
|---|---|---|---|
| **0.0000** | 0.1464927 | 0.0708493 | **5.33e-15** |
| 0.0010 | 0.1464905 | 0.0708572 | 6.00e-06 |
| 0.0020 | 0.1464838 | 0.0708808 | 1.04e-05 |
| 0.0030 | 0.1464728 | 0.0709199 | 1.18e-05 |
| 0.0040 | 0.1464577 | 0.0709744 | 8.49e-06 |
| **0.0050** | 0.1464385 | 0.0710438 | **9.47e-07** |
| 0.0060 | 0.1464155 | 0.0711278 | 1.80e-05 |
| 0.0100 | 0.1462924 | 0.0715993 | 1.90e-04 |
| 0.0150 | 0.1461011 | 0.0724454 | 7.26e-04 |

**두 개의 골(k3 = 0, ≈0.005) 사이에 1.2e-5 THz 의 장벽**이 있다. 즉 nodal line 이
아니라 **분리된 노드 두 개**이고, 거울대칭으로 k3 = −0.005 에 하나 더 있어 3개다.
앞 절 결론 그대로다.

**다만 앞 절 표의 "gap = 0" 은 다듬어야 한다.** Nelder-Mead 가 보고한 값이 아니라
직접 평가하면:

| k | gap (THz) |
|---|---|
| (0.1464927, 0.0708493, 0) | 5.3e-15 |
| (0.1464400, 0.0710381, ±0.0049255) | 1.3e-07 |

바깥 두 노드의 정확한 위치는 아직 1e-4 수준으로만 잡혀 있다(골이 너무 얕아
정밀화가 잘 안 된다). 위상 전하는 그래도 확정적이다 — 아래.

## 9. "노드가 가까워서 생긴 문제" 맞다 — 그런데 결론은 안 바뀐다

노드 간격이 0.005, 사이 장벽이 1e-5 THz 다. 반지름 0.001~0.002 인 구는 기하학적으로
이웃을 안 품지만 이웃의 Berry curvature 가 강하게 새어 들어온다. 그래서

- Simphony 는 `Nk1=Nk2` 를 100 이상 줘야 감김을 잡고 (15, 50 은 조용히 0),
- 가운데 노드는 Nk=200 에서도 개별값이 0 으로 나온다.

그러나 **위상 전하는 적분값이라 두 방법이 독립적으로 같은 답을 준다**:

| 구 | Simphony | Berry flux |
|---|---|---|
| k3=+0.0049 하나만 | −1 | +1 |
| k3=−0.0049 하나만 | −1 | +1 |
| k3=0 하나만 | (0, 수렴 실패) | −1 |
| **셋 다 감싸는 R=0.010** | **−1** | **+1** |

가운데가 0 이라면 감싸는 구가 ∓2 여야 한다. 실제로는 ∓1 이다.
**Simphony 자신의 합 규칙이 가운데 노드가 대전돼 있음을 말한다.** Berry flux 는
반지름 0.0005~0.002, 격자 32×64 / 48×96 전부에서 −1 로 흔들리지 않는다.

결론: **알짜 전하 ±1 의 Weyl 삼중 구조**이며, 이 판정은 두 독립 방법의 합 규칙으로
뒷받침된다. 개별 노드값의 불안정성은 Simphony 구면 격자의 수렴 문제이지 물리가 아니다.

# 정정 — 가운데 노드도 Simphony 가 직접 χ = ±1 을 준다 (Nk2 를 올리면 된다)

앞 9절에서 "가운데 노드의 개별값 0 은 Simphony 수렴 실패이며 합 규칙으로만 뒷받침된다"
고 썼는데, **수렴시킬 수 있다.** 필요한 것은 `Nk2`(Wilson loop 개수)다.

## 10. 원인 — 추정부가 아니라 loop 해상도

`wannier_center3D_weyl_func_kpoints` 의 chirality 추정부는 단순 언랩이다:

```fortran
gap_step= wcc_sum(ik2+1)- wcc_sum(ik2)
if (abs(gap_step+1)<abs(gap_step)) gap_step= gap_step+ 1
...
chirality= nint(gap_sum)
```

즉 **인접 loop 사이 WCC 변화가 0.5 를 넘으면 언랩이 반대로 간다.** 이 노드는
적도 근처에서 WCC 가 매우 급하게 움직여서, loop 이 성기면 한 스텝에 0.7 씩 뛴다:

```
Nk2=61  기준 적도 근방 WCC:  0.0205 -> 0.2836 -> 0.9824      (스텝 0.70 -> 언랩 실패)
Nk2=801 기준 적도 근방 WCC:  0.99999 -> 0.00000              (연속 통과 -> 언랩 성공)
```

`SELECTED_OCCUPIED_BANDS` 를 `17` 하나로 줄여 WCC 를 곡선 하나로 만들어도 결과는
같았다(0). 즉 **largest-gap 다발성 문제가 아니라 순수한 θ 방향 해상도 문제**다.
같은 기하·같은 방식(overlap 곱 Wilson loop)을 phonopy 고유벡터로 재현하면
Simphony 와 정확히 같은 답이 나오므로, **Simphony 쪽 버그가 아니다.**

## 12. 최종 — 두 방법이 완전히 일치한다

| 구 | Simphony | Berry flux (독립 구현) |
|---|---|---|
| k3 = +0.0049255 | −1 | +1 |
| **k3 = 0** | **+1** | **−1** |
| k3 = −0.0049255 | −1 | +1 |
| 셋 다 감싸는 구 | **−1** | **+1** |

전체 부호 규약만 반대고 **개별값·상대부호·합이 전부 일치**한다.
(−1) + (+1) + (−1) = −1 ✓ — Simphony 안에서 합 규칙이 닫힌다.

**결론은 앞 절 그대로다**: 알짜 전하 ±1 의 Weyl 삼중 구조, 거울 4점 궤도까지
합쳐 BZ 전체에 12개, 에너지 **41.72 meV (336.5 cm⁻¹)**.
바뀐 것은 "가운데 노드는 합 규칙으로만 안다" → **"Simphony 가 직접 준다"** 이다.

## 13. 재현 시 반드시

- `Nk1` 은 loop 위 점 개수, **`Nk2` 는 loop 개수(θ 방향)** 다. 이렇게 무른 노드는
  **`Nk2 ≥ 800`** 이 필요하다. `input.py` 기본값 50 은 물론 200 도 부족하다.
- 계산량이 크니(Weyl 1개에 수 분) 후보를 좁힌 뒤 마지막 확인에만 쓰면 된다.
  바깥 노드들은 `Nk2 = 100` 이면 이미 맞는다.

# 14. Weyl 이 Γ-X 에 가까워 보이는 건 사실이다 — 그런데 갈 수 있는 선은 Γ-S 다

`(0.1464927, 0.0708493, 0)` 에서 표준 고대칭선까지의 카테시안 거리:

| 선 | 거리 (1/Å) | 대칭 |
|---|---|---|
| **Γ-S** | **0.0659** | **거울면 밖 (제약 없음)** |
| Γ-X | 0.0891 | k2 = 0 **거울면** → χ=0 강제 |
| Γ-R | 0.1273 | 거울면 밖 |
| Γ-U | 0.1554 | k2 = 0 거울면 |
| Γ-Y | 0.1769 | k1 = 0 거울면 |

**Γ-X 가 가까워 보이는 건 착시가 아니다.** Γ-X 위 `k1 = 0.1465` 에서 band17-18 gap 이
**0.0747 THz = 0.309 meV** 밖에 안 된다. 밴드 그림에서는 거의 닿은 것처럼 보인다.
(같은 k1 에서 k2 를 0 → 0.0708 로 옮기면 gap 이 7.47e-2 → 5.5e-4 THz 로 닫힌다.)

## 그러나 Γ-X 위에는 올라갈 수 없다

parent_pristine 의 거울지표는 **k1, k2** 다. Γ-X = (t, 0, 0) 은 **k2 = 0 거울면 안**이므로
χ=0 이 강제된다. 게다가 그쪽으로 밀면 `(0.1465, −0.0708, 0)` 의 **반대 부호 짝과 만나
소멸**한다. 즉 "Γ-X 로 옮긴다"는 곧 "없앤다"이다.

## Γ-S 가 더 가깝고, 대칭 제약도 없다

Γ-S = (t, t, 0) 은 k1, k2 가 **둘 다 변하고** k3 = 0(편극축)만 고정이다 → 거울 제약 없음.
게다가 Weyl 이 이미 살고 있는 **C2·T 불변 평면(k3=0) 안**이라, 평면 안 이동만으로
도달한다. **대칭을 하나도 깰 필요가 없다.**

```
최근접점        (0.10714, 0.10714, 0)   t = 0.214
필요한 이동     (−0.0394, +0.0363, 0)   크기 0.0535 (환산) = 0.0659 1/Å
그 지점 현재 gap  0.1347 THz = 0.557 meV
```

> Γ-S 는 seekpath 기본 경로에는 없지만 고대칭점 두 개를 잇는 선이고, 경로에 대각선
> 구간을 추가하는 것은 통상적이다. `results/weyl_trend/SUMMARY.md` 의 "거울지표가
> 하나도 고정되지 않는 8개 선" 목록에 들어 있는 그 선이다.

## 이건 이미 알려진 그 기하학적 사실이다 (축 규약만 다름)

pristine_mirror 규약(편극축 = k2)에서 "strain ray 가 **Γ-U 대각선과 거의 평행**하고
수직 offset 이 0.049" 라고 한 것과, parent 규약(편극축 = k3)에서 "Weyl 이 **Γ-S 대각선**
에서 0.054 벗어나 있다"는 것은 **같은 사실**이다. 편극축=0 평면의 대각선이 규약에 따라
Γ-U 또는 Γ-S 로 불릴 뿐이다.

따라서 함의도 같다:

- **strain 만으로는 못 닫는다.** 응답 행렬이 rank-1 이고 ray 가 하필 그 대각선과
  거의 평행하다. 제2의 대칭보존 손잡이(조성 x, 극성 진폭 λ = 1−2x, 질량)가 필요하다.
- **Γ-X 를 굳이 목표로 하려면** glide 를 깨서 P2₁ 로 가야 한다(불균등 180° 도메인).
  그러면 k2=0 의 χ=0 강제가 사라지고, 거울 짝과의 소멸 구속도 풀린다.

## 정리

| 목표 | 거리 | 대칭을 깨야 하나 | 막는 것 |
|---|---|---|---|
| **Γ-S** | 0.0659 1/Å | **아니오** | strain 응답이 rank-1 → 제2 손잡이 필요 |
| Γ-X | 0.0891 1/Å | **예 (P2₁)** | k2=0 거울면 χ=0 강제 + 거울 짝과 소멸 |

## 16. 노드의 국소 구조 — type-II 이고, 편극축 방향으로 거의 평평하다

PPT 그림(fig 5)을 만들다가 확인한 것. 노드 `(0.1464927, 0.0708493, 0)` 주위에서
band 17/18 을 3차원으로 전개했다 (phonopy, R=0.004 rlu, 9³ 격자, 최소제곱).

```
ω±(Δk) = ω0 + v·Δk ± |M Δk|,   ω0 = 10.08703 THz
```

| 양 | 값 (reduced 좌표, THz/rlu) |
|---|---|
| tilt `v` | `(+2.4384, −0.1141, 0)` |
| 콘 주축 기울기 | `1.1192` (방향 `(−0.734, −0.679, 0)`) |
| | `0.7619` (방향 `(−0.679, +0.734, 0)`) |
| | `≈0.003` (방향 `(0,0,1)` = 편극축 c) |
| tilt 파라미터 `T = √(vᵀA⁻¹v)` | **2.748** |

### 16.1 type-II 다

`T > 1` 이므로 **type-II (overtilted) Weyl point** 이다. 눈으로 바로 보이는 증거는
`k_a` 를 따라 자른 밴드다 — 두 가지가 **둘 다 위로** 올라간다:

```
 Δk_a      E17        E18
-0.0100  10.053227  10.072732
+0.0000  10.086936  10.086936
+0.0100  10.102042  10.121465
```

tilt 2.44 > 콘 기울기 0.97 (그 방향 성분). `k_b` 방향은 정상적인 콘이라
E17 은 노드에서 최대, E18 은 최소가 된다.

결과적으로 `ω = ω0` 등주파수면이 점이 아니라 **노드에서 맞닿은 두 개의 열린
포켓**이다. fig 3 의 아크 그림에서 배경 무늬로 그대로 보인다.

### 16.2 편극축 방향으로는 사실상 2차원이다

`k_c` 만 움직이면 gap 이 **2차로** 자란다:

```
   k_c        gap(THz)     log-log 기울기
0.0005     4.6938e-06
0.0010     1.5155e-05        1.691
0.0020     5.6425e-05        1.897
0.0080     8.8170e-04        1.994
0.0160     3.5338e-03        2.003
```

면내는 정확히 1차다 (`gap = 1.944 × Δk_a`, 기울기 1.000).

2차처럼 보이는 이유는 선형항이 없어서가 아니라 **너무 작아서**다.
`gap = 2√(α²s² + β²s⁴)` 로 맞추면 `β ≈ 6.9`, `α ≈ 0.0032 THz/rlu` 이고
교차점은 `s ≈ α/β ≈ 4.6e-4 rlu`. 위 표에서 `s=0.0005` 의 기울기가 1.69 로
2에서 벗어나기 시작하는 게 바로 이 지점이다.

즉 **선형 Weyl point 는 맞다** (그래서 χ=±1 이 나온다). 다만 편극축 방향
속도가 면내의 **1/350** 이라 준2차원이다. 이게 왜 중요하냐면:

- `WeylChirality_calc` 구면 반지름 `r0 = 0.0015 (1/Å) ≈ 0.0012 rlu` 는
  교차점보다 바깥이다. 구면 위에서 극(±k_c) 근처 gap 이 적도의 1/100 수준으로
  작아진다 → **Wilson loop 이 성기면 조용히 0 이 나오는** 13절 현상의 근본 원인.
  `Nk2 = 801` 이 필요했던 이유가 이것이다.
- 편극 평면 안에서만 보면 완전한 2D Weyl(=Dirac-like) 처럼 행동한다.
  `(2₁∥c)·T` 가 `k_c=0` 평면의 모든 k 를 고정시켜 Hamiltonian 을 실수로 만들기
  때문에 평면 안에서 노드는 codim-2 로 일반적이다.

### 16.3 발표에 쓸 문장

> 이 바일 포논은 편극 평면 안에서 강하게 기울어진 type-II 노드이고
> (tilt 파라미터 2.75), 편극축 방향 속도는 면내의 1/350 이라 사실상
> 준2차원이다. 등주파수면은 점이 아니라 노드에서 맞닿은 두 포켓이다.

### 17.1 `fermiarc.f90` 이 LO-TO 를 건너뛴다 (`patch/apply_fermiarc_loto_fix.py`)

### 17.2 `dos_l_only` 정규화 오류 (`patch/apply_surfdos_only_norm_fix.py`)

`dos.dat_l` 의 4번째 열(표면 전용 DOS)이 전 구간 `0.99999997E-09` 였다.

```fortran
do i= 1, NtopOrbitals      ! = 36  (표면 단위포 하나)
   dos_l = dos_l - aimag(GLL(io,io))
do i= 1, Ndim              ! = 72  (주층 = Np * Num_wann)
   dos_bulk = dos_bulk - aimag(GB(i,i))
...
dos_l_only = dos_l - dos_bulk        ! 궤도 개수가 두 배 차이인데 그냥 뺀다
if (dos_l_only < 0) dos_l_only = eps9
```

`Np = 2` 면 벌크를 두 배로 빼는 셈이라 **항상 음수 → 전부 eps9 로 잘린다.**

`fermiarc.f90` 에는 `_only` 출력이 아예 없어 fig3/fig4 스크립트가 후처리로
계산한다 (PN.out 에서 `NtopOrbitals` 와 `ndim` 을 읽는다).

### 17.4 사영 벌크 간극 — 이전 계산이 틀렸다 (정정)

**이전 판정 "커버리지 1.000, 간극 없음" 은 지표를 잘못 짠 결과다.**
`(어떤 밴드든 ω0 이하) AND (어떤 밴드든 ω0 이상)` 을 커버리지로 쟀는데,
이건 음향 가지가 아래 있고 광학 가지가 위에 있으면 어디서나 참이라 항상
1.000 이 나온다.  아무 의미가 없는 수였다.

제대로 된 지표는 **각 `(k_a, k_b)` 에서 `k_c` 로 사영했을 때 ω0 을 실제로
지나는 밴드 개수** `nb` 다.  161×113×61 격자로 다시 계산:

```
nb 분포        0: 7676   1: 6466   2: 4051     (전체 18193)
진짜 간극(nb=0) 비율          0.4219
창 안에서 ω0 을 지나는 밴드    17, 18, 19  — 단 3개
노드 (0.14625, 0.07143)      nb = 2  (band 17, 18 둘 다)
```

"36개 가지가 빽빽해서 묻힌다" 는 설명도 틀렸다.  이 주파수에서 관여하는
밴드는 **17, 18, 19 세 개뿐**이고, 표면 BZ 의 **42 %는 진짜 간극**이다.

`band 17/18 만` 기준으로 보면 간극 비율이 역시 0.4219 이고, 그 **경계 곡선이
네 바일 사영점을 정확히 지난다** (노드에서 가장 가까운 간극 점까지 거리
0.0036 = 격자 간격 수준).  경계는 노드에서 가장 안쪽(k_a=0.1465)이고
`k_b`=0 에서 0.163, `k_b`=±0.15 에서 0.19 로 벌어진다.  노드가 경계의
잘록한 지점이다 — 아크가 있어야 할 기하 그대로다.

(`nb = 2`) 안에 있다.

**가장 유력한 원인은 종단면이다.**  현재 자르는 면은 c 축 방향으로 가장 넓은
빈틈(0.2510)이라 결합을 가장 적게 끊는 가장 불활성한 벽개면이다.  이런 면은
미결합 손이 없어 간극 속 표면 상태가 잘 안 생긴다.  층 구조:

```
층 z (편극축 방향):  0.0088  0.1204  0.2578  0.5088  0.6204  0.7578
빈틈:                0.1116  0.1374  0.2510  0.1116  0.1374  0.2510
```

세 가지 벽개면이 있고 현재는 0.2510 면이다.  다른 두 면으로 자르려면
POSCAR 원자를 c 방향으로 강체 이동시키면 된다 (`scripts/figs/shift_termination.py`).
H(R) 은 강체 이동에 불변이라 hr.dat / BORN 을 다시 만들 필요가 없다.

| 자를 면 | shift |

| 빈틈 0.1116 | 0.9354 |
| 빈틈 0.1374 | 0.8109 |
| 빈틈 0.2510 (현재) | 0.6167 |

### 17.6 m0.8 과 종단면 3종 — 전부 음성

"간극은 있는데 표면 상태가 없다"가 종단면 탓인지, 구조 탓인지 갈랐다.

**종단면 3종 (parent_pristine).**  `pn.in` 의 `ATOMS` 카드를 편극축으로
강체 이동시켜 세 벽개면을 각각 노출시켰다 (`scripts/figs/shift_termination.py`).
⚠️ Simphony 는 좌표를 **POSCAR 가 아니라 pn.in** 에서 읽는다 — POSCAR 만
밀면 아무 일도 안 일어난다 (이걸로 한 번 헛돌았다).

| shift 0.9354 | 0.9442 | 0.1116 | 최대 0.414, 중앙값 0.366 |

### 17.7 ⚠️ 근본 원인 후보 — 슬랩이 음향 총합 규칙을 위반한다

`SlabBand_calc`, NSLAB=20 으로 Γ점 모드를 봤다:

```
Γ 최저 12개 (THz):
 -0.35352   0.30099   0.37550   0.46374   0.58312   0.58600
  0.63790   0.68558   0.71652   0.73620   0.83515   0.85667
```

물리적인 슬랩이라면 **음향 모드 3개가 정확히 0** 이어야 한다.  실제로는
허수 모드 하나(−0.354 THz)에 나머지가 0.30 THz 부터 시작한다.
**표면에서 ASR 이 깨져 있다.**

원인은 구조적이다.  슬랩은 hr.dat 를 층 방향으로 잘라 만드는데, 끊긴 결합의
비대각 힘상수는 사라지지만 **대각(자기) 항에는 그 이웃의 기여가 그대로 남는다.**
전자 TB 모델이면 문제가 없지만 동역학 행렬에서는 표면층에 가짜 복원력이
생긴다.  제대로 하려면 슬랩 동역학 행렬에 ASR 을 다시 부과해야 한다
(각 원자에 대해 `Φ_ii ← −Σ_{j≠i} Φ_ij`, 질량 스케일된 D 에서는
`D_ii ← D_ii − Σ_j √(m_j/m_i) D_ij`).

**다만 이것이 10 THz 대의 아크 부재를 설명한다고 단정할 수는 없다.**
ASR 위반의 크기(0.35 THz)는 음향 영역에서 두드러지고, 10 THz 광학 영역에
얼마나 영향을 주는지는 확인하지 않았다.  그래도 결함이 **표면층에**
있고 아크가 사는 곳도 표면층이라는 점에서 가장 유력한 후보다.

`SlabArc`/`SlabSS` 의 반무한 Green 함수는 모든 층에 같은 `H00` 을 쓰므로
표면층만 고친 `H00_surf` 를 넣을 수 없다 — 구조적 한계다.  유한 슬랩
(`SlabBand_calc`)은 전체 행렬을 명시적으로 만들므로 ASR 보정을 넣을 수 있고,
층 사영 무게로 표면 상태를 골라내는 게 포논 아크를 보는 표준 방법이기도 하다.

### 17.8 현재 결론

- 사영 벌크 간극은 실재하고 그 경계가 네 바일 사영점을 정확히 지난다.
  아크가 있을 기하는 갖춰져 있다.
- 그런데 네 번의 독립 표면 계산에서 간극 안 표면 상태가 전혀 없다.
- 슬랩 구성에 ASR 위반이라는 실재하는 결함이 있어 **음성 결과도 결정적이지
  않다.**  "아크가 없다" 고 단정하면 안 된다.
- 다음 단계는 ham_slab 에 ASR 보정을 넣고 `SlabBand_calc` + 층 사영으로
  다시 보는 것이다.  그 전까지 표면 관련 정량 주장은 보류한다.

### 17.9 미해결 — 슬랩 LO-TO 가 표면 거울 대칭을 깬다

이 표면(법선 ∥ c)은 z 이동이 없는 a-glide(⊥b)를 그대로 가지므로
`dos(k_a, k_b) = dos(k_a, −k_b)` 여야 한다.  그런데:

| 검사 | 편차 |
|---|---|
| 반전 `(k_a,k_b) → (−k_a,−k_b)` (시간역전) | **0.000e+00** (정확) |
| 거울 `k_b → −k_b` | log DOS 중앙값 **0.024**, 최대 **0.66** (전체 범위 7.8) |
| 벌크 phonopy 의 같은 거울 | **1e-7 THz** (정확) |
| SlabSS 의 같은 거울 | 중앙값 0.036, 최대 0.76 |

입력(hr.dat, BORN)은 멀쩡하고, SlabSS 도 같은 크기로 어긋나므로 17.1 패치가
만든 것도 아니다.  `ham_qlayer2qlayer_LOTO` 의 슬랩 per-k LO-TO 항 쪽으로
보인다.  의심 가는 곳: `k3d` 를 면내 두 성분으로만 재구성하고 면직 성분을
0 으로 두는 부분, 그리고 `LOTO_qdir_run` 을 `ek_bulk`/`ek_slab` 만 설정하고
`surfstat`/`fermiarc` 는 설정하지 않는 부분.  **원인은 아직 못 짚었다.**

그림에서는 알려진 대칭으로 평균만 냈다 (`fig3_arc.py` 의 `SYM`).
정량적 결론(아크 위치 등)에 쓰기 전에 원인을 밝혀야 한다.
